# Day Care, Eggs, gender ratios and connection status

Consolidated state for October 25, 2026. The [Spanish delivery summary](es/changes-2026-10-25.md) contains the complete feature matrix, contracts, evidence and remaining checks.

## Delivered behavior

- **Shared Day Care:** Black and X use normalized readings and injected services. X adds validated, read-only Save and Citra live readers. Slots show individual gender, current level, total EXP and estimated steps; unavailable, empty and stale readings remain distinct.
- **Egg notification:** a floating Egg shortcut opens Day Care when a current reading confirms an Egg is ready. It does not wait for evolution metadata and disappears when the Egg is no longer available or the reading becomes stale.
- **X hatching progress:** Egg cards in the party and boxes show remaining cycles and a progress bar against the species' normal initial cycles. Party cards include an estimated step range without hatching bonuses. Boxes explain that the Egg must join the party to advance. Black does not yet expose this counter.
- **Gender ratios in Captures:** one proportional blue/pink bar, localized labels and rounded percentages. A single-gender species shows only its 100%; genderless species retain their symbol. Black and X calculate their own base probabilities before passing them to shared presentation. These are not combined encounter/capture probabilities and do not apply Cute Charm or forced-gender rules.
- **Shared connection indicator:** Manual, Save and Live states, reader details, timestamps and a callback to open connection controls. X boxes are informational and never affect the button's color. Black retains its independent general/battle readers.

## Contract boundaries

| Contract | Shared data/presentation | Game adapter responsibility |
| --- | --- | --- |
| `DaycareReading`, `DaycareData`, `DaycareService` | Availability, stale state, slots, total EXP and services | Save/memory format, species/forms, growth and evolution rules |
| Saved roster hatching fields/services | Individual remaining cycles, species baseline and cycle length | Read the counter and supply the selected game's metadata/rules |
| `GenderDistribution` | Calculated male/female percentages | Historical gender calculation |
| `ConnectionStatus`, `ConnectionReaderStatus` | Declared readers, localized messages, timestamps and `affectsSummary` | Normalize source states and select which readers affect the summary |

Game and source remain separate choices. Presentation does not select endpoints, parse save bytes or infer capabilities from a game name. Black's existing APIs and workspace composition remain deliberate legacy boundaries. No universal adapter, new dependency or mandatory configuration was introduced.

The hatching reference table can be refreshed with `node scripts/update-x-hatch-cycles.mjs`. It downloads fixed public metadata for X's 721 species and never uses save-derived queries. Step estimates do not read the within-cycle phase or apply Flame Body, Magma Armor or O-Powers. Memory support remains limited to the locally validated X profile, not all X/Y revisions.

## Validation record

The last code delivery passed **394 tests, lint and build**. This documentation update does not repeat those checks. Earlier counts in detailed notes are historical.

Real X checks covered empty Save Day Care, occupied live slots, individual genders, EXP changes, Egg availability, reading recovery through disconnect/reconnect, live Egg counters/progress, gender ratios in Captures and connection status across Manual/Save/Live. Desktop, 390 px layouts and Spanish/English were checked in the deliveries.

Fixtures covered malformed/corrupt data, incomplete reads, optional failures, unknown fields, reference bounds, gender edge cases and connection state aggregation. A populated real Save Day Care, restart/savestate recovery and a controlled full hatching sequence remain unverified. Black's connection regression used tests/fixtures rather than a new real melonDS session.
